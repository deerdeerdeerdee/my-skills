# 指定产品与目标市场

在用户明确“将产品 X 卖到国家/地区 Y”时使用本模式。目标是判断一个可管理的产品与市场组合，是否有值得验证的 B2B 采购机会，交付可追溯的产品比较、潜在采购企业与开发草稿。网络能力、动态原页、账号和实际外部动作沿用 [工具与证据规则](tool-routing.md)。

## 输入与范围

最少输入是产品名称/参考链接和目标国家/地区。不要求用户先找客户、供应商或买家痛点。读取项目已有预算、时间、业务模式、授权与台账；沿用已确认模式，未明确时以 B2B 寻源研究作为说明的默认假设。外部动作按实际授权执行，缺少授权时只研究和准备草稿。

先简述本批产品定义：用途、主要规格或档次、目标市场，以及哪些条件由用户固定。只有泛品名时，结合当地在售款选择一个代表规格并标为研究假设；关键歧义会改变产品用途、市场准入或买家类型时再澄清。已有具体 SKU 时保留其身份，参照款和替代款另列，不能把相近产品当作同规格。

选择能回答本批问题的城市、渠道或应用切片。沿用主文件的默认批次上限或用户指定范围，不把一个国家展开成全行业扫描。国家和产品是本批边界；证据不支持时交付原因及调整建议，由用户决定是否换方向。

## 研究路径与决策

下列环节可按证据情况交叉推进；遇到可能否定可行性的条件时优先核验，避免先堆积客户名单。

| 环节 | 需要形成的判断 | 足够支持下一步的材料 |
| --- | --- | --- |
| 产品与用途 | 实际研究的是哪一种产品，适合谁使用 | 参考款/候选 ID、关键规格、用途、固定条件和待核项 |
| 当地市场与门槛 | 当地通过什么渠道销售；有哪些重要进入条件 | 原始商品页、品牌/渠道官网、用户材料；与具体用途相关的官方规则和有效日期 |
| 采购企业与角色 | 谁可能买货用于转售、品牌经营、项目或自用 | 公司经营证据、相关产品/项目、渠道角色、官方联系入口及采购机制线索 |
| 采购理由 | 为什么值得考虑这个产品或我们这一供货选择 | 已观察到的交易条件或使用任务、现有方案、候选变化、客户价值假设及反证 |
| 中国供给与成本 | 是否存在规格匹配且有初步交易可行性的公开供给 | 当前 1688 具体变体、MOQ、价格类型、包装等；成本条件、来源和缺口 |
| 开发与决策 | 哪个对象值得验证什么，何时继续或停止 | 个性化首问、合适角色、最小下一步、待核条件与退出理由 |

### 当地产品和渠道

按需要组合当地电商/零售目录、品牌与分销官网、用户评价/专业讨论、展会或协会目录、官方贸易数据和公开采购信息。搜索使用当地语言或当地常用产品名称；保留本批读到的范围与盲区，不把个性化热销榜当全市场。

市场存在、产品使用需求和企业当前采购意向分别核验。销量标签、缺货、进口统计或同类产品在售，都不能单独证明某家企业正在找中国供方。贸易数据口径可能覆盖更大的产品集合；记录产品分类依据、年份和粒度，不能直接当作目标 SKU 的需求量。

比较当地款与中国候选时，保留型号、关键规格、数量/计价单位、币种、是否含税/运费、包装/配件、服务和观察日期。零售价、批发价和 1688 国内展示价分开；品牌、售后、渠道费用或规格不同造成的价差不能直接算作利润。

按用途初筛可能涉及的产品要求、运输限制、知识产权、进口主体或渠道准入；适用性未明确时保留待核，不能凭相似产品推定合规。不要在通用模块中硬编码某国税率、认证结论或运费。

### 采购企业与采购理由

区分最终使用者、零售商、批发商/进口商、品牌商、项目承包商与代理；终端评论可支持使用任务，通常不能直接提供 B2B 采购对象。判断对方是直接进口、向当地分销商采购、品牌授权经营还是自有品牌；找不到证据就标未知，并说明为什么适合或不适合当前个人 SOHO。

常规补货、第二供应商、合适的 MOQ、定制、总成本、质量一致性、交期或组合供货，都可以成为采购理由。无需为标准产品强行编造新品痛点，也不能仅凭“中国可找到”推断更便宜、更稳定或更适合。

逐对象写清：对方现售/使用什么 → 本产品与其采购角色的关系 → 我们拟提供的具体选择 → 支持证据和未证假设 → 最容易验证的下一步。保留本地现货、已有稳定供方、独家渠道、规模错配或服务成本等反证。

### 中国供给与初步成本

客户回复前可以研究 1688 公开供给；不要求先联系工厂或取得完整出口报价才能筛选机会。按具体变体记录当前页面条件；“功能标杆”“待核可供候选”“同规格候选”分开，不强行补满 SKU 数量。

估算只用于判断可行性：分别列产品、定制/包装、国内物流、国际运输、税费/清关、支付及异常处理等适用项，注明数量、条款、币种、来源和承担方。未知费用留待核；有依据的区间可做敏感性比较，不能填零、用零售差价算利润或输出虚假精确的成交概率。关键门槛未明时给出“待条件确认”的结论。

买家确认用途、规格、数量、目的地和交期后，再按项目闸门与实际授权冻结 RFQ、重新读页面并取得可比书面供方条件。市场研究、联系供应商、正式报价、样品与采购分别记录。

## 交付与开发草稿

原位更新本批台账和少量必要卡片；不为每个环节新增报告。沿用已有稳定 ID，新增条目保留批次和发现路径，链接原始证据。最终交付包含：

- **范围与结论**：产品/市场边界、实际覆盖、继续/条件继续/停止及决定性证据。
- **产品比较**：当地参照款与中国候选的规格、MOQ、计价条件、差异、不可比项及未知成本；不以行数代替匹配质量。
- **优先采购企业**：沿用批次上限，给出经营背景、渠道/采购角色、相关产品、当前采购信号是否已证、采购理由、反证、官方入口和待核项。数量不足就如实交付。
- **逐对象开发草稿**：一个具体观察、一项与对方采购角色相符的产品/供货建议、一个容易回答的下一步。常规产品可问适用规格或供应商评估入口；新品搭配可核是否值得进一步比较。不要一封堆完资格问卷。
- **验证计划**：最多三项下一动作，指出要补哪个字段、满足什么条件才升级，以及哪些动作已获授权/仅有草稿/实际执行。

存在可核验企业、相关采购角色或可核的路由、具体采购理由和基本供给可行性时，可以准备资格首问；采购意向不必在首问前已证实，但必须明确仍是待验证对象。发送仍按用户实际授权，不能把进入名单当作获准联系。

关键证据不足时，交付缺口和最小验证计划；明确不可行时停止。访问受阻不等于市场无需求；两次无信息增量按主文件停止该对象，不为满足数量换成无关客户或 SKU。完成本批后结束，等待新证据或用户确定下一批。
